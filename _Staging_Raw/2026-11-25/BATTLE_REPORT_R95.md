## 七、生产事故复盘（本轮触发原因）

### 事故 1：GitHub CI 连续红（用户来信触发）
- **现象**：2026-11-25 16:22 master 构建 `45575753434` 失败，L1 步骤 exit 1，L2 被 skip。
- **根因链**：`_tools/dl_gate.py` 硬编码 `LIB = r"C:\Library"` → Linux runner 无此目录 → glob 空 → 打印 `no files to scan` **且不写报告** → 工作流内联脚本 `glob(...)[-1]` 抛 `IndexError` → 步骤失败。**不是编译失败，是空列表取下标**。
- **修复**：库根三级解析（`DAOLI_LIB` > 脚本父目录 > 兜底）+ 工作流两步在「报告缺失」时打印提示并 `exit 0`，不再以异常形式挂流水线。
- **教训**：`|| true` 吞掉上游失败后，下游仍按「必有产物」假设取下标——**吞错必须配套存在性判据**。

### 事故 2：僵尸锁 24 小时，产线静默停摆
- **现象**：`.round.lock` 停留在 `ROUND=R95 / START=2026-11-25T23:05`，至 2026-11-26 23:06 仍在。
- **后果**：R95 之后**整整一天无新增**（registry 停在 2,041，磁盘已 2,081），40 件成品成为孤儿。
- **处置**：删锁；40 件补裁决后全部入库。
- **教训**：收尾删锁必须放在**独立步骤且失败也执行**；建议改为「锁带心跳时间，超 100′ 自动判僵尸并归档到 `.round.lock.zombie`」而非静默跳过。

### 事故 3：80 件成品未提交（R94 40 + R95 40）
- **现象**：本地 333 个未跟踪文件；`git add -A` 反复失败。
- **根因**：① R94 的后台 `git add -A` 被中断，留下 `.git/index.lock`；② 子代理把 127MB 开源包解到 `_Staging_Raw/2026-11-25/_pkg/`，其中 Beckhoff 样例路径超 Windows 长度上限 → `Filename too long` → 整个索引失败。
- **处置**：清锁；`_pkg/` 与 `_Staging_Raw/2026-11-24/`（26k 文件 dump）入 `.gitignore`；按交付物范围选择性提交 171 文件。
- **教训**：**子代理禁止在工作目录解压外部仓库**，只能解到系统临时目录。
